# UC-USR-05: View User Audit History

| **Use Case ID:**             | UC-USR-05                                                       |
|------------------------------|-----------------------------------------------------------------|
| **Use Case Name:**           | View user audit history                                         |
| **Created By:**              | System Admin       | **Last Updated By:**   | —           |
| **Date Created:**            | 2026-05-17         | **Date Last Updated:** | —           |

---

| **Actor:**                   | Primary: **System Admin**                                       |
|------------------------------|-----------------------------------------------------------------|
| **Description:**             | The System Admin reviews the change history of a specific user account to investigate past modifications, verify compliance, or support troubleshooting. The system displays a chronological list of audit log entries showing which admin made what change, when, and what values changed. |

---

| **Preconditions:**           | 1. Admin is authenticated with role `admin`. 2. Admin is on the Edit User page for a specific user (`/users/:id/edit`). 3. At least one audit log entry exists for the target user. |
|------------------------------|-----------------------------------------------------------------|
| **Postconditions:**          | 1. Admin has reviewed the audit history. No data is modified. |
| **Priority:**                | Medium — used for compliance investigation and support.         |
| **Frequency of Use:**        | ~3–10 times per week (compliance checks, incident investigation). |

---

| **Normal Course of Events:** |                                                                 |
|------------------------------|-----------------------------------------------------------------|
|                              | 1. Admin navigates to the Edit User page (`/users/:id/edit`). |
|                              | 2. System displays the Edit User form and, alongside it, an Audit History sidebar panel. |
|                              | 3. System fetches the audit log entries for this user from the server. |
|                              | 4. System renders the most recent 10 audit entries in the sidebar, each formatted as: *"[Admin Name] changed [Field] from '[old value]' to '[new value]' on DD/MM/YYYY HH:mm"*. |
|                              | 5. Admin reads the audit history to understand past changes. |

---

| **Alternative Courses:**     |                                                                 |
|------------------------------|-----------------------------------------------------------------|
| UC-USR-05.AC.1               | **No audit entries exist** — At step 4, if no audit log entries are found for this user, System renders the sidebar with the message: *"No changes recorded for this user yet."* |

---

| **Exceptions:**              |                                                                 |
|------------------------------|-----------------------------------------------------------------|
| UC-USR-05.EX.1               | **Audit log API error** — At step 3, if the server returns an error, System shows an error message inside the sidebar: *"Could not load audit history."* The Edit User form remains functional. |
| UC-USR-05.EX.2               | **Admin session expired** — At any step, if the auth token expires, System redirects to the login page. |

---

| **Includes:**                | — |
|------------------------------|-----------------------------------------------------------------|
| **Special Requirements:**    | 1. **Privacy**: Audit history is visible only to admins; regular users cannot access this view. 2. **Performance**: Audit log panel loads within 1s independently of the form. 3. **Display**: Maximum 10 most recent entries are shown; older entries are not paginated in current scope. 4. **Format**: Changed fields are rendered in human-readable format (field name + old/new values). |
| **Assumptions:**             | 1. The audit sidebar shows only the most recent 10 entries (no pagination or "Load more" in current scope). 2. Audit log data is never deleted, even after the target user is deleted. 3. All admin actions (create, update, delete) are tracked and visible in this panel. |
